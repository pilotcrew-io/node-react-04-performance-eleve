# React · Mesurer et améliorer le catalogue

**Atelier 04/06 · 4 h 30 · nr-04-performance**

Le catalogue doit rester compréhensible quand une personne change rapidement de recherche ou de page. L’équipe veut savoir quelles optimisations sont utiles, et demande des traces comparables plutôt qu’un score annoncé sans contexte.

Ce dépôt contient les instructions, les mémos et les espaces de travail. **Le code est à construire ; aucune solution terminée n’est fournie dans le dépôt élève.** Les acquisitions précédentes sont reprises avant la séance selon [Day 0](DAY0.md).

## À la fin de la séance

- Piloter recherche, catégorie, tri et pagination depuis l’API.
- Annuler les lectures devenues inutiles et protéger l’état contre les réponses tardives.
- Interpréter LCP, INP et CLS en distinguant laboratoire et terrain.
- Comparer une correction ciblée dans des conditions reproductibles.

## Déroulé de 270 minutes

| Séquence | Minutes |
| --- | --- |
| Protocole et mesure initiale | 30 |
| Recherche et pagination | 55 |
| Annulation et réponses tardives | 50 |
| Analyse et correction ciblée | 55 |
| Comparaison et tests | 55 |
| Revue et remise | 25 |

Répartition cible de cette séance : **225 min frontend / 45 min backend**, tests et revue de chaque couche inclus. Sur le cursus : **18 h frontend et 9 h backend**. Cette dominante React est un choix pédagogique, pas un ratio chiffré attribué à l’annonce.
